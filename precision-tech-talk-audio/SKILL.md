# Precision Tech Talk · 声音后期

把已经剪辑完成的口播视频做成具有统一栏目听觉识别的声音版本。声音必须服务叙事和人声，不能把每个画面变化都铺成模板音效。

## 输入门槛

开始前必须取得用户上传或明确给出本地路径的已剪辑成片，并确认文件可读取。把它视为 picture lock：后续所有时间码以该文件为唯一真源。

- 只有文案、SRT、原始口播或零散镜头时，不推测音效时间码；要求先提供剪辑好的成片。
- 成片应保留清晰对白，最好尚未烘焙 BGM 和音效。若已有不可分离的音乐且用户要替换，要求提供无音乐版本或对白分轨。
- 先用 `ffprobe` 核对时长、帧率、分辨率、音轨、采样率和声道，再做完整或抽样解码。
- 如果画面剪辑、变速或片长后来改变，原事件表和混音必须失效并重新分析，不能整体平移时间码蒙混过关。
- 不覆盖输入成片；所有分析、素材和输出放到独立 `audio-post/` 或用户指定的工作目录。

## 工作模式

按用户当前要求做到对应阶段，不强制一次完成全部流程：

1. **只分析**：输出情绪曲线、视觉事件时间线和声音机会点。
2. **只生成提示词**：输出一条完整 BGM 提示词及去重后的唯一音效提示词。
3. **生成素材**：使用用户指定的本地模型、正版素材库或已登录服务生成并验收文件。涉及付费前先取得明确授权。
4. **完成混音**：把已确认的 BGM 和音效铺回锁定成片，输出新版本与验收报告。

## 分析顺序

先读 [成片分析与事件时间线](references/analysis-and-event-timeline.md)，提取关键帧并完成三遍分析：叙事情绪、镜头节奏、可听化动作。事件必须记录动作发生点、持续时间、声源物体、力度、距离、方向和情绪作用。

需要生成 BGM 或音效时再读 [BGM 与音效生成](references/bgm-and-sfx-generation.md)。先完成事件表，再按声音家族去重；同一种 UI tick、数字变化或证据卡声音只生成一次，通过剪辑参数复用。

需要把声音加入视频时再读 [混音与验收](references/mixing-and-qa.md)。对白始终居中且优先；BGM 用能量自动化和侧链避让，音效按声源位置、景深和叙事级别空间化。

## 不变量

- 不直接提取或复制参考博主的音乐、音效或混合原声；只抽象节奏、密度、频谱和情绪特征，使用原创或授权素材。
- BGM 通常全片只用一首，通过分段自动化形成起伏；除非叙事结构明确需要换章。
- 普通字幕、每句话结尾和所有转场不自动配音。只为状态改变、逻辑落点、物体动作、证据揭示和章节转换配声。
- 生成音效优先要干净干声，不把声像和长混响烘焙进去；空间位置在混音阶段统一完成。
- 重复音效必须复用同一资产；允许通过裁切、增益、声像、轻微音高与空间处理形成递进。
- 外部生成结果逐个核对文件名、格式、时长、峰值、可解码性和实际听感；下载成功不能代替验收。
- 视频流优先无损复制，只重编码最终音轨。保留上一版本，不静默覆盖。

## 标准交付

按任务阶段交付以下文件中的相关部分：

- `BGM生成提示词.md`
- `事件时间线与完整音效表.md`
- `精简音效资产库与复用表.md`
- `audio/generated_sfx/` 与 BGM 原始文件
- 可重复执行的项目混音脚本或等价工程
- 新版本 MP4 与 `混音验收报告.md`

可从 `assets/` 中的三个模板开始填写。最终报告至少写明输入成片、输出时长、BGM/音效数量、总响度、真峰值、音频规格、完整解码结果和已知限制。

## 用户最简输入

> 使用 `$precision-tech-talk-audio`，为我上传的已剪辑科技口播成片分析情绪和动作，生成一套原创 BGM 与去重音效，并在我确认素材后完成混音。视频在【路径】。
