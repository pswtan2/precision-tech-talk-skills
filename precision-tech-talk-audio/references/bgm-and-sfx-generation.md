# BGM 与音效生成

## BGM 提示词

先根据成片写一条可执行的音乐 brief，必须包含：

1. 精确或略长于成片的时长；
2. 内容类型、听众和旁白类型；
3. 栏目气质与情绪边界；
4. BPM 或脉冲速度、调性色彩、主要音色；
5. 按时间码描述的能量曲线与最终落点；
6. 为中文咬字留空间的频谱要求；
7. 禁止人声、强主旋律、夸张鼓组和可识别版权旋律等负面约束。

科技商业口播的安全起点通常是 88–105 BPM、低旋律密度、暗色合成器氛围、稀疏数字脉冲和克制次低频。它不是固定风格；应服从实际视频情绪。

生成模型无法严格遵守时间码时，不反复浪费额度。生成一条稳定、可循环、具有足够尾音的音乐床，再在混音阶段用音量自动化塑造章节能量。

## 音效去重

先把完整事件表聚类为声音家族，例如：

- 品牌 UI tick
- 数字上升 / 下降 blip
- 证据卡打开
- 章节 swipe / whoosh
- 逻辑锁定
- 警示低频 hit
- 机械运动底声
- 物体碰撞或压合
- 大空间数据中心氛围
- 最终结论 impact

语义相同、材质相同、力度接近的事件只生成一个源文件。剧情级动作可以独立生成。输出“唯一资产表 + 全时间线复用表”，不要把几十个节点错误地变成几十个随机音色。

## 单条音效提示词结构

每个提示词写清：

`声源物体 + 动作 + 材质 + 力度 + 距离 + 期望干声 + 精确时长 + 起音/尾音 + 禁止项`

示例结构：

> 一个近距离玻璃质感数字界面完成锁定，力度中等，起音清晰、尾音很短，0.35 秒，干净干声，无背景音乐、无人声、无长混响、无卡通感、无失真。

方向和空间混响通常不写入生成提示词，在混音阶段处理。若生成服务会自动加入氛围，明确要求 isolated、dry、clean one-shot。

## 生成与验收

- 优先 48kHz WAV；无法提供时保存平台最高质量原文件，不先转码。
- 每个资产通常生成 2–4 个候选，按声源可信度、起音、尾音、噪声和频谱选择，不默认选择第一个。
- 文件名用稳定编号，如 `A01_brand_ui_tick.wav`；拒绝候选移入单独目录，不与正式资产混放。
- 批量下载后逐个核对 RIFF/编码头、实际时长、声道、采样率、峰值和完整解码。
- 网页端连续下载可能复用临时文件名；每次通过生成历史、提示词或修改时间确认文件归属。
- 用户指定本地免费模型时优先本地生成。使用付费服务或消耗额度前说明成本并取得授权。
- 参考视频只用于提取抽象声音特征，不下载、分离或复刻其受版权保护的原声。
