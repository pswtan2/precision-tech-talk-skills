# 语义驱动的动效规划

## 从 SRT 生成语义计划

逐条读取字幕，以口播开口时间为准，合并成完整语义单元。为每个单元输出：

| start | end | 原句 | 传播目的 | 画面类型 | 关键内容 | 来源 | 退出规则 |
|---:|---:|---|---|---|---|---|---|

`start` 是第一个相关词真正说出口的时间；`end` 是论点讲完或下一个论点开始前。画面不能早于 start 泄露答案，默认在 end 前 6–10 帧开始退场。

## 语义到画面的映射

| 文案信号 | 推荐画面 |
|---|---|
| “从 A 涨到 B、增长 X%” | 主数字计数 + 对比条 + 来源 |
| “因为 A，所以 B，最后 C” | 流程链 / 因果箭头，节点随口播点亮 |
| “三类公司争抢同一资源” | 多来源汇入单一容量池 |
| “过去/现在、方案 A/B” | 左右对比或时间轴 |
| “第一、第二、第三” | 决策列表，当前项亮、已讲项降透明度 |
| “官方报告/财报显示” | 可读的真实网页证据卡 + 局部放大 + 页码 |
| 抽象概念或机制 | 简化示意图、B-roll 或产品拆解，避免伪造统计数字 |
| 结论/金句 | 真人全屏 + 单一大字，不叠加复杂图表 |

## 信息价值判断

每个覆盖元素至少满足一项：帮观众看懂关系、让数字更直观、证明事实来源、降低记忆成本或明确可执行建议。

“SOURCE CHECK”“BUYING DECISION”“3 STEPS”这类仅重复栏目名、没有新增含义的装饰字应删除或换成具体信息。

## 真实网页证据

优先级：官方报告/IR/监管文件 > 权威研究机构原文 > 一线媒体 > 聚合与二手转载。

1. 保留足够的网站/报告身份信息。
2. 同屏展示局部放大的关键数据，数字最小应能在手机端看清。
3. 用高亮框、箭头或重构卡说明“观众应该看哪里”。
4. 来源行写机构、报告名、日期和页码；不要只写模糊域名。
5. 若原网页太密，主画面使用重构数据卡，旁边保留小型原页作为证据锚点。

## 避免重复和拖尾

- 每个场景组件必须有明确的 `from` 与 `to`。
- 同一概念在后文再次出现时，判断是在递进还是重复；递进应换成新关系图，重复则不再显示。
- 场景切换时先让旧信息在 6–10 帧内退出，再让新信息进入。
- 在每个边界后 0.3–0.5 秒抽帧检查：上一段元素应完全消失。
