# Precision Tech Talk · 风格初始化

把用户的审美和制作约束变成可执行的视频生产线。用户可能不懂设计或代码，因此一次只讨论一个决定，先解释它影响什么，再给少量清晰选项。

## 固定流程

```text
已有信息复述 → 逐步问卷 → 2–3 版效果图 → 用户选版/迭代
→ 完整确认单 → 生成模板套件 → Remotion 真实渲帧 → 交付调用方式
```

1. 开始问卷前读 [访谈指南](references/interview.md)。用户已经说过的信息先复述求证，不重复追问。
2. 问卷结束后读 [效果图与确认](references/preview-and-confirmation.md)。必须让用户看图选择，不能仅凭形容词直接定稿。
3. 用户明确确认最终方案后，才读 [产物与验收](references/output-contract.md)，并开始写最终模板文件。

## 对话纪律

- 默认一次只问一个话题；每题提供 2–4 个互斥选项，并标出推荐项及影响。
- 用户说“不知道”“你决定”时，选择适合其平台与内容形态的默认值，并明确记录。
- 已知信息可以一次打包求证，未知信息不能批量轰炸。用户明确要求一次答完时可以合并问卷，但效果图选择和最终确认不能省略。
- 风格问题只问方向、参考和禁用项；圆角、阴影、字号等细节通过效果图比较确定。
- 在用户选定效果图并确认总方案之前，除了预览 HTML/PNG，不创建最终工程、不覆盖现有模板。

## 最终交付

生成一个以用户命名的模板目录，至少包含：

- `STYLE-PROFILE.md`：人可读的视觉、字幕、动效、声音和素材规范。
- `style-profile.json`：颜色、字号、圆角、动画、画幅等机器可读参数。
- `PROMPT-TEMPLATE.md`：以后每期复制填写的开工提示词。
- `starter/`：从 `assets/starter/` 定制的可运行 Remotion 工程。
- `previews/`：最终选中的效果图与真实渲帧。

运行 `scripts/validate_template.py <模板目录>`，再安装依赖并至少渲染钩子、信息卡和字幕三类关键帧。验收失败必须修复后再交付。

## 初始化调用

> 使用 `$precision-tech-talk-setup`，通过一步一步的问卷和效果图，帮我建立一套自己的科技口播模板。不要直接套默认风格，等我确认最终效果后再生成工程。
